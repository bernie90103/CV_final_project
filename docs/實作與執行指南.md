# 第六組期末專案：研究說明與 Windows 重現指南

本專案研究 PatchCore 如何定位面積很小的工業瑕疵。資料來自 MVTec AD 的 screw、capsule、metal_nut 三類。我們比較 WideResNet50-2 的 layer2、layer3、兩層融合特徵，並測量定位準確度、記憶庫大小與推論時間。PatchCore 是既有方法；本組的工作是小瑕疵分組、同容量比較與實驗分析。研究範圍見 `docs/group6_proposal.pdf`，最終英文報告在 `output/pdf/group6_patchcore_final_report.pdf`。

快速閱讀：[期末報告](../output/pdf/group6_patchcore_final_report.pdf)、[目前進度](PROJECT_STATUS.md)、[組員新增資料索引](組員新增資料索引.md)、[錄影報告指南](錄影報告指南.md)。

以下路徑和指令都以**專案根目錄**為起點。請先在 PowerShell 切換到包含 `README.md`、`run_experiment.py` 的資料夾，再執行程式。

## 研究設計

只用正常訓練圖片建立各類別的 PatchCore 記憶庫，測試時才使用異常圖片和標註。小瑕疵的定義是原始標註面積佔原圖面積不超過 1%；分組在縮圖與裁切前就固定。主要指標是小瑕疵 AUPRO@0.3，pixel AUROC 和 image AUROC 作為補充。

主實驗有 3 類資料 × 3 種特徵 × 3 個 coreset 種子 × 2 種輸入尺寸，共 54 次。輸入尺寸為 224 和 320 像素，使用 10% approximate greedy coreset。另有 27 次實驗固定在 224 像素，每個模型保留 4096 個 1024 維 float32 向量，向量儲存量為 16 MiB。固定向量數讓三種特徵在相同記憶庫容量下比較；峰值 RAM、GPU 記憶體和特徵提取成本仍可能不同。

資料檢查顯示：screw 有 118 張小瑕疵、1 張較大瑕疵；capsule 分別有 85 和 24 張；metal_nut 分別有 7 和 86 張。少量樣本的分組只適合描述，不宜過度推論。中心裁切會移除部分標註像素，但沒有任何異常圖片失去全部瑕疵像素。

## 程式如何運作

`study/data.py` 找出 MVTec AD 的正常訓練圖與測試圖，計算原始標註面積，再處理圖片和 mask 的縮放與裁切。`study/model.py` 使用凍結的 WideResNet50-2 抽取 patch 特徵，從正常訓練圖建立 coreset 記憶庫。測試時用 FAISS 找最近的正常特徵，將距離轉成異常分數與熱力圖。`study/metrics.py` 計算 AUPRO@0.3 和 AUROC。

根目錄的 `run_experiment.py` 執行一組設定，`run_matrix.py` 排程所有類別、特徵與種子，`summarize_results.py` 匯總結果。原實驗電腦保留 `results/runs_windows/formal/` 的完整設定與逐張預測；GitHub 版提供摘要表、比較結果與報告圖片，若需檢查逐張紀錄，請向保管原始實驗輸出的組員索取。

## 第一次安裝

首次從 GitHub 取得專案時，在 PowerShell 執行：

```powershell
git clone --recurse-submodules https://github.com/bernie90103/CV_final_project.git
cd CV_final_project
```

接著在專案根目錄執行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu130
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe download_data.py
.\.venv\Scripts\python.exe prepare_weights.py
.\.venv\Scripts\python.exe -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

CUDA 檢查應顯示 `True` 和 RTX 5060（其他支援 CUDA 的電腦會顯示自己的顯卡）。之後每次直接使用 `.\.venv\Scripts\python.exe`，無須啟用虛擬環境。資料下載會從 MVTec 官方來源取得檔案，請預留下載與解壓時間；資料集的使用條款請見 `THIRD_PARTY.md`。如果是在原實驗電腦上操作，資料和權重已存在，無須重複下載。

`requirements-windows-lock.txt` 記錄首次 RTX 5060 實驗使用的確切套件版本。

## 檢查資料

```powershell
.\.venv\Scripts\python.exe inspect_dataset.py --size 224
.\.venv\Scripts\python.exe inspect_dataset.py --size 320
```

小瑕疵是原始 mask 面積佔原圖不超過 1% 的異常圖片。螺絲只有一張較大瑕疵、金屬螺帽只有七張小瑕疵，這些分組只能謹慎描述。原圖經等比例縮放再中心裁切，mask 以最近鄰方式處理；部分瑕疵會被裁掉，`results/audit/` 有逐張紀錄。

## 跑正式實驗

```powershell
.\.venv\Scripts\python.exe run_experiment.py --category screw --layers fusion --seed 0 --device cuda --output results/runs_windows --resume
.\.venv\Scripts\python.exe run_matrix.py --sizes 224 --device cuda --output results/runs_windows
.\.venv\Scripts\python.exe run_matrix.py --sizes 320 --device cuda --output results/runs_windows
.\.venv\Scripts\python.exe summarize_results.py --root results/runs_windows --output results/summary_windows
```

兩種尺寸各 27 組、總共 54 組，依序執行。這些實驗已完成；重跑前請先確認是否真的需要重新計算。`--resume` 只會跳過設定與資料、程式雜湊完全相同的完成實驗。單組輸出中的 `complete.json` 表示已完成；`metrics.json`、`runtime.json` 和 `examples/` 分別提供指標、時間與可視化。RTX 5060 執行特徵提取與 coreset 抽樣，FAISS 最近鄰搜尋在 CPU。記憶庫向量大小不代表峰值 GPU 記憶體。

也可執行 `run_windows_matrix.cmd` 一次跑兩種尺寸，進度記錄在 `results/windows_matrix.log`，成功後自動更新 `results/summary_windows/`。

正式結果請以產品和圖片尺寸分開讀。表中的平均值與樣本標準差來自三個 coreset 種子；只有一個 seed 時不能計算這項標準差。舊 Mac 結果放在 `results/legacy_mac/`，不混入 Windows 摘要或速度比較。

## 固定記憶庫分析與單圖展示


完成 baseline 後，產生單張圖片的熱力圖：

## 如何讀取結果

在所有三類資料與兩種尺寸中，layer2 的小瑕疵 AUPRO@0.3 都高於 layer3。融合特徵接近 layer2，但沒有穩定勝過它。固定 16 MiB 記憶庫後，screw 的 layer2 與融合分別為 0.9593、0.9505；capsule 分別為 0.9733、0.9719。metal_nut 的融合只高出 0.0002，而該小瑕疵分組只有七張異常圖片。

將輸入由 224 提升至 320 像素後，九個類別與特徵組合的小瑕疵 AUPRO 都上升。layer2 在 screw、capsule、metal_nut 的增量分別為 0.0139、0.0130、0.0011，平均延遲約變成三倍。縮放與平滑的相對尺度也同時改變，所以這不是只改變解析度的獨立因果實驗。

`results/summary_windows/mean_std.csv` 是做簡報圖表時最方便的表格。`results/audit/size224/defect_area_histograms.png` 顯示小瑕疵分布；`results/figures/` 有三類的輸入、標註及熱力圖對照。完整數值和限制以七頁英文報告為準。影片尚未錄製，錄影與交件步驟見 `docs/錄影報告指南.md`。
